## Findings

### Keep

- A CMS package boundary for future Payload adoption.
- A small typed content contract that can be consumed by `apps/web` later.
- `withCMS` as an inert Next config hook only if it has no provider dependencies.

### Refactor

- Current `@repo/cms` is BaseHub-specific despite no active consumers.
- BaseHub-generated type file is provider-generated surface and should not remain in the clean active package.
- BaseHub component wrappers are provider-specific UI and currently unused.
- `BASEHUB_TOKEN` env key is no longer an active product env contract.
- BaseHub dev/build/analyze scripts are stale and can reintroduce build/codegen coupling.
- README and operating memory still mention the old `apps/web -> @repo/cms -> BaseHub` build blocker, which is no longer accurate after web stopped consuming CMS.

### Delete

- `basehub` dependency.
- `basehub.config.ts`.
- `basehub-types.d.ts`.
- `components/body.tsx`, `components/code-block.tsx`, `components/feed.tsx`, `components/image.tsx`, `components/toc.tsx`, `components/toolbar.tsx`.
- `keys.ts` / `@repo/cms/keys` export until Payload env is intentionally introduced.
- BaseHub scripts and `.env.example`.

### Defer

- Payload install.
- Payload App Router `(payload)` files.
- `payload.config.ts`.
- Payload Postgres migration strategy.
- Payload admin auth policy.
- Payload storage adapter.
- CMS localization and preview flow.
