## Findings

### Keep

- Better Auth server config in `src/server.ts`.
- Better Auth React client in `src/client.ts`.
- Next App Router route-handler adapter in `src/next.ts`.
- T3 Env key definition in `keys.ts`.
- Auth validation schemas in `src/validations/auth.ts`.
- Email verification, password reset, social auth, and organization plugin direction.

### Refactor

- `@repo/auth/middleware` is unused and owns route policy that should be app-local. `apps/app/proxy.ts` is the active Next 16 proxy implementation.
- Root `index.ts` re-exports middleware helpers, making an unused app-policy surface look canonical.
- The package has no package-local tests even though its password/email schemas are reusable cross-app contracts.

### Delete

- `packages/auth/lib/validations/auth.ts` is stale old auth validation. It has weaker password constraints and is not exported or consumed.
- `packages/auth/types/index.d.ts` is stale app/web config typing. It imports `@/components/icons` from inside a package, which violates the package boundary and was already flagged in the app surface audit.

### Defer

- Full Better Auth end-to-end flow tests with a real database, Resend, and OAuth callbacks belong in the later app/auth integration test phase.
- Organization invitation URL route (`/accept-invitation/:id`) needs a future app route decision.
- User/account/session database schema conformance to Better Auth generated schema belongs to P2.2 `@repo/database`.
- Resend transport behavior belongs to P2.3 `@repo/email`, though auth email hooks may be smoke-tested through package/app tests.
