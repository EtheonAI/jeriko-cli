## Evidence Rule

Each research note must include:

- Date researched
- Source URL
- Source type: official docs, code, paper, or competitor/product observation
- Claim
- Evidence
- Impact on implementation
- Open questions

## Package Refactor Rule

Before refactoring any package API, framework integration, config surface, or runtime boundary:

- Check current official docs.
- Check latest package release/version.
- Inspect installed package types or local source when useful.
- Inspect current repo usage.
- Document the evidence if the decision affects architecture.
- Then implement the smallest change that matches the evidence.
