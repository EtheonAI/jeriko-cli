# Package Ownership Index

Date: 2026-05-24

## Purpose

This index prevents the active `packages/*` folder from becoming another junk drawer.

Per Turborepo's package model, active packages should be reusable library/config packages that support deployable apps. Application packages should stay at the end of the graph, not become hidden dependencies of other packages.

Sources:

- `https://turborepo.com/repo/docs/core-concepts/package-types`
- `https://turborepo.com/repo/docs/reference/package-configurations`
- `https://vercel.com/docs/monorepos`

## Package-First Rule

Apps are deployable shells and route owners. Packages own reusable provider SDKs, config adapters, shared UI primitives, env key contracts, runtime libraries, and their package-local contracts.

Before editing an app to add or repair shared behavior:

1. identify the owning `@repo/*` package;
2. repair or add its public export;
3. consume that export from the app;
4. remove app-local provider/config dependencies that are no longer app-owned.

Do not import package internals from apps just because a path alias resolves.

## Rules

- Do not add new product code to `legacy/*`.
- Do not create nested active package globs such as `packages/backend/*` without changing `pnpm-workspace.yaml` intentionally.
- Do not add package dependencies from reusable packages back into application packages.
- Do not add provider SDK internals to apps when an owning package exists.
- Do not import non-exported package subpaths from apps.
- App `next.config.ts` files compose package-owned config contributors; they do not own provider integration details.
- Keep env validation package-local and feature-local; do not rebuild broad app env aggregators.
- Before deleting any package, run source search for imports, check package graph, and document replacement or archive reason.
